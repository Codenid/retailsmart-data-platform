# RS-010 — Happy path de insights en tiempo real

## Ejecución

```bash
export CLOUDSDK_CONFIG=/tmp/retailsmart-gcloud
python3 scripts/streaming/insights_pipeline.py \
  --runner=DataflowRunner \
  --project=retailsmart-bigdata \
  --region=us-central1 \
  --job_name=rs010-insights-demo \
  --input_subscription=projects/retailsmart-bigdata/subscriptions/rs-dev-str-ps-events-dataflow \
  --output_topic=projects/retailsmart-bigdata/topics/rs-dev-str-ps-insights \
  --requirements_file=scripts/streaming/requirements.txt \
  --staging_location=gs://rs-dev-str-gcs-dataflow-rsg/staging \
  --temp_location=gs://rs-dev-str-gcs-dataflow-rsg/tmp \
  --service_account_email=rs-dev-str-sa-dataflow@retailsmart-bigdata.iam.gserviceaccount.com \
  --num_workers=1 --max_num_workers=1 --autoscaling_algorithm=NONE
```

Publicar un único evento válido con `event_id` nuevo y leer la suscripción
`rs-dev-str-ps-insights-consumers`. No hacer pull de
`rs-dev-str-ps-events-dataflow` durante la ejecución.

## Observabilidad

Los logs del worker son:

- `EVENTO_RECIBIDO` inmediatamente después de Pub/Sub.
- `EVENTO_DESCARTADO` con el motivo.
- `INSIGHT_GENERADO` con `source_event_id`.

## Cierre

Cancelar el job y verificar:

```bash
gcloud --project=retailsmart-bigdata dataflow jobs cancel JOB_ID --region=us-central1
gcloud --project=retailsmart-bigdata dataflow jobs describe JOB_ID \
  --region=us-central1 --format='value(currentState)'
```

La aceptación exige leer en `rs-dev-str-ps-insights-consumers` un insight cuyo
`source_event_id` coincida con el `event_id` enviado.
