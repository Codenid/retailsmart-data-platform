# RS-003 — Fundación GCP

## Estado

Scripts y pruebas locales preparados. El despliegue requiere identidad activa,
proyecto y facturación verificables. RS-003 no crea Composer, clústeres
persistentes Dataproc ni jobs Dataflow.

## Prueba local

```bash
bash scripts/tests/test_common.sh
bash scripts/verify-local.sh
bash scripts/gcp/01-setup.sh --dry-run
```

## Verificación manual en Cloud Console

1. Seleccionar el `PROJECT_ID` configurado y confirmar billing habilitado.
2. Revisar APIs, cuentas de servicio y roles; no debe existir Owner/Editor asignado por estos scripts.
3. Revisar que los recursos RetailSmart tengan labels `retailsmart=true`, `environment=lab` y `managed-by=retailsmart`.
4. Confirmar que no se creó Composer, un clúster Dataproc ni un job Dataflow.
5. Ejecutar `bash scripts/gcp/02-status.sh` y comparar con IAM, Storage, Pub/Sub y BigQuery.
6. Repetir `01-setup.sh --dry-run`; no debe proponer duplicados.

La primera ejecución real de `01-setup.sh` verificó proyecto, identidad, billing y
las 13 APIs objetivo. Durante una repetición posterior, las consultas de `gcloud`
respondieron intermitentemente después de billing; no se detectaron procesos
pendientes ni recursos adicionales. Repetir desde Cloud Shell si se requiere
evidencia de la segunda ejecución completa.

## Costos y limpieza

La fundación usa servicios de consumo. Composer, clústeres persistentes y otros
recursos de costo fijo significativo quedan fuera hasta mostrar una estimación y
obtener autorización. `99-destroy.sh` no elimina recursos automáticamente.
