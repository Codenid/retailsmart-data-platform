# RS-004 — Storage Landing, Bronze y Silver

## Ejecución

```bash
export CLOUDSDK_CONFIG=/tmp/retailsmart-gcloud
bash scripts/tests/test_storage.sh
bash scripts/gcp/03-storage.sh --dry-run
bash scripts/gcp/03-storage.sh
bash scripts/gcp/03-storage.sh
```

El script conserva buckets existentes con ubicación correcta y crea únicamente
los faltantes. No crea objetos de estado ni elimina buckets u objetos.

## Verificación manual

En Cloud Console → Cloud Storage → Buckets, revisar los cuatro nombres esperados,
ubicación `us-central1`, acceso uniforme, prevención de acceso público y labels.
Los prefijos son contractuales y aparecerán cuando los pipelines escriban datos:
Landing batch por productor, Bronze raw por modalidad, Silver curado por modalidad
y modelos de demanda versionados.

## Seguridad y costos

No se conceden permisos públicos ni se crean claves. Los buckets usan labels de
laboratorio y clasificación interna. El costo es variable por almacenamiento y
operaciones; no se crean recursos de costo fijo significativo.

## Limpieza

`99-destroy.sh` no elimina estos buckets. Toda limpieza futura requiere una
decisión explícita, `PROJECT_ID`, confirmación interactiva y exclusión del estado
sintético persistente.
