# RS-009 — Happy path streaming hacia Silver

## Alcance

La demo ejecuta únicamente:

```text
Pub/Sub events-dataflow -> Dataflow/Beam -> SilverEventWriter -> GCS Silver
```

Bronze conserva la suscripción `events-raw`. Cuarentena, DLQ, auditoría,
ventanas y deduplicación quedan fuera del recorrido de esta demo académica.
`SilverEventWriter` escribe un objeto JSON por evento usando credenciales del
worker y una ruta estable: `eventos/demo/DEMO_RUN_ID/EVENT_ID.json`.

## Prueba local

```bash
python3 -m unittest tests.test_dataflow_pipeline tests.test_stream_processor -v
bash scripts/verify-local.sh
```

La prueba local valida el contrato mínimo y comprueba que los reintentos del
escritor usarían la misma ruta por evento.

## Ejecución GCP

```bash
export CLOUDSDK_CONFIG=/tmp/retailsmart-gcloud
export PROJECT_ID=retailsmart-bigdata
export REGION=us-central1
export DEMO_RUN_ID=rs009-$(date -u +%Y%m%dT%H%M%SZ)
export EVENT_ID=evt-stream-0004
export JOB_NAME=rs009-demo-${DEMO_RUN_ID}
export SUBSCRIPTION=projects/${PROJECT_ID}/subscriptions/rs-dev-str-ps-events-dataflow
export SILVER_BUCKET=retailsmart-dev-data-gcs-silver-rsg
export DATAFLOW_SA=rs-dev-str-sa-dataflow@${PROJECT_ID}.iam.gserviceaccount.com

gcloud --project="$PROJECT_ID" pubsub subscriptions describe \
  rs-dev-str-ps-events-dataflow

python3 scripts/streaming/dataflow_pipeline.py \
  --runner=DataflowRunner \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --job_name="$JOB_NAME" \
  --streaming \
  --input_subscription="$SUBSCRIPTION" \
  --silver_bucket="$SILVER_BUCKET" \
  --demo_run_id="$DEMO_RUN_ID" \
  --requirements_file=scripts/streaming/requirements.txt \
  --staging_location=gs://rs-dev-str-gcs-dataflow-rsg/staging \
  --temp_location=gs://rs-dev-str-gcs-dataflow-rsg/tmp \
  --service_account_email="$DATAFLOW_SA" \
  --num_workers=1 \
  --max_num_workers=1 \
  --autoscaling_algorithm=NONE
```

Con el ID devuelto por Beam, verificar el estado:

```bash
gcloud --project="$PROJECT_ID" dataflow jobs describe JOB_ID \
  --region="$REGION" --format='value(currentState)'

gcloud --project="$PROJECT_ID" pubsub topics publish rs-dev-str-ps-events \
  --message="$(tr -d '\n' < tests/fixtures/streaming/store-iot.json)"
```

Verificar logs y el objeto:

```bash
gcloud --project="$PROJECT_ID" logging read \
  'resource.type="dataflow_step" AND textPayload:"Subida Silver exitosa"' \
  --limit=20 --format='value(timestamp,textPayload,jsonPayload)'

gcloud storage cat \
  "gs://${SILVER_BUCKET}/eventos/demo/${DEMO_RUN_ID}/${EVENT_ID}.json"
```

El contenido leído debe conservar el `event_id` del fixture y sus campos del
contrato. La URI solo se registra después de completar la subida.

Comprobar la rama Bronze de forma independiente:

```bash
gcloud --project="$PROJECT_ID" pubsub subscriptions describe \
  rs-dev-str-ps-events-raw --format='yaml(name,topic,ackDeadlineSeconds)'
```

Cancelar siempre el job y confirmar `JOB_STATE_CANCELLED`:

```bash
gcloud --project="$PROJECT_ID" dataflow jobs cancel JOB_ID \
  --region="$REGION"
gcloud --project="$PROJECT_ID" dataflow jobs describe JOB_ID \
  --region="$REGION" --format='value(currentState)'
```

## Limitación académica

La escritura de un objeto por evento simplifica la demostración y no pretende
resolver volumen, compactación ni exactly-once productivo. Los reintentos usan
la misma ruta y contenido; la aceptación depende de leer el objeto real en GCS.
